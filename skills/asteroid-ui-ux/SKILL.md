# Asteroid UI/UX 工作流

这份 skill 是 Asteroid 的项目适配层。它把 `ui-ux-pro-max` 的检查规则降为证据工具，优先服从当前代码、内容密度、中文阅读场景和用户审查，不套用数据库里的旧风格模板。

## 触发范围

当任务涉及页面布局、阅读宽度、字号、动效、交互反馈、响应式、页面流畅度、工具入口整理或视觉审查时使用本流程。纯文案、数据迁移、后端接口和编辑器内部逻辑不走本流程，除非用户明确把它们列入范围。

## 目标与冻结基线

开始改动前先记录本次阶段的四项内容：

1. **主任务**：用户在页面上要完成什么，成功条件是什么。
2. **真实入口**：目标 route、代表性内容、当前加载/错误/空状态。
3. **主验收画布**：桌面横屏 `2560×1440`；辅助画布为 `390×844`，必要时补 `768×1024`。
4. **不变边界**：本阶段不涉及的内容、数据、权限、编辑器或外部服务。

项目现有令牌和组件优先级高于新建议：

- 版心、颜色、间距和响应式规则：`app/globals.css`、`components/ui/PageScaffold.tsx`。
- 动效时长、缓动和弹簧：`lib/motion.ts`。
- 全局导航、页面过渡和 reduced-motion：`components/layout/Navbar.tsx`、`components/layout/PageTransition.tsx`、`hooks/usePrefersReducedMotion.ts`。

## 六步执行

### 1. 建立基线

先打开真实 route，读取代表性长标题、公式、题目卡片和错误/加载状态。记录版心、导航高度、正文字号、行高、关键控件命中区、页面总宽度和横向溢出。

完成条件：主任务、目标画布、当前数值和不变边界都有明确记录；没有只凭截图猜测的问题。

### 2. 排序问题

按以下顺序处理发现：

1. 任务完成、可访问性和错误恢复；
2. 导航位置、交互反馈、焦点和触控命中区；
3. 响应式版心、文字可读性、长内容换行和固定层遮挡；
4. 加载与运行性能；
5. 字体、颜色、装饰和动效。

每个问题写成“证据 → 用户影响 → 最小修正”。区分客观缺陷、待验证假设和个人偏好。外部优秀项目只能提供候选做法；必须说明它与 Asteroid 的阅读任务、内容密度和中文字体是否匹配。

完成条件：本阶段只保留一个最小、连续的改动范围；不把整站重做混进一个阶段。

### 3. 冻结可测量规格

改代码前冻结本阶段需要的值：

- 页面版心、列数、间距、侧栏和断点；
- 正文字号、行高、最大阅读行长；
- 控件高度、左右内边距、图标尺寸和最小命中区；
- 动效时长、缓动、位移/缩放范围和中断方式；
- 加载、空、错误、禁用、成功、展开/收起和 reduced-motion 行为。

优先复用已有 token。新增数值必须能解释为内容约束、设备约束或现有比例尺的一部分。

完成条件：验收者能用浏览器测量结果判断通过或不通过，而不是依赖“看起来更好”。

### 4. 做 vertical slice

只实现一个从入口到结果的完整切片，例如：笔记目录 → 阅读页、工具入口 → 训练页、首页 hero → 学习规划。保留真实内容，优先改共享组件或预设，避免为单页复制一套样式。

动效规则：

- 动效解释状态变化或层级关系；不为装饰阻塞内容。
- 连续 `requestAnimationFrame` 必须在不可见、页面隐藏或 `prefers-reduced-motion` 时暂停。
- 过渡可被用户中断；加载超过约 300ms 要有状态反馈。
- 键盘焦点、滚动位置、返回路径和移动端触控不因动效丢失。

完成条件：主流程可运行，关键状态至少有一个非默认状态，改动仍处于用户明确范围内。

### 5. 浏览器验收

在真实本地 route 上检查：

- `2560×1440`：版心、导航、封面/正文比例和首屏节奏；
- `390×844`：文字收缩、菜单、控件命中区和横向溢出；
- 代表性长标题、公式、代码块和图片；
- 鼠标与键盘的主流程、focus-visible、加载和错误恢复；
- reduced-motion 与控制台错误；
- 固定/粘性元素是否遮挡正文，页面是否保存可预期的滚动和返回状态。

浏览器截图和 DOM 测量是 UI 证据；lint、类型检查、测试和构建只能证明代码门禁，不能替代视觉验收。

完成条件：目标 route 在两个冻结画布上打开成功，横向溢出为零，主交互完成，控制台没有本阶段新增错误。

### 6. 阶段交付与人工门控

每个阶段结束时只交付当前切片，说明：已完成、未处理、验证命令、浏览器测量、已知限制和下一阶段候选。展示截图或可运行 route 后暂停，等待用户回复“通过/继续”或修改意见。

用户通过后才能扩大范围；用户提出修改时只回到当前阶段重新测量和展示。没有通过前，不批量扩展页面、不提交、不推送、不把半成品描述为完成。

## 交付状态

使用以下状态词：`audit complete`、`implemented locally`、`prototype verified`、`deployed`、`production verified`。本地构建成功只能标记代码门禁通过；只有目标 route 的浏览器检查完成后，才能称为 `implemented locally`。
